# Office操作の実機採取

目的は、PADの左欄から追加したアクションをコピーし、Excel・Word・PowerPointの依頼に再利用できるRobinの根拠を集めることです。以下の操作は採取対象であり、PADの実在するアクション名や対応機能の一覧ではありません。

2026-09-07、PAD 2.71.115.26224からOfficeの17種類・22設定例を採取しました。最初は画面を取得できませんでしたが、ユーザーがデザイナーを表示した後に再開しています。Computer Useでは設定ダイアログの入力が反映されなかったため、ユーザーの明示承認で直接Windows UI Automationへ切り替えました。その後はComputer Useを併用していません。

|---|---|---|

基本16操作は空サブフローへの再貼付け・再コピーがバイト一致しました。既存文書の再読取り・置換の11操作も、採取原文のインスタンス参照とExcel出力変数名を明示的に揃えて組み立て、再コピーのバイト一致と実行を確認しています。元の3ファイルのハッシュは不変でした。索引は [catalog/index.json](../catalog/index.json)、証拠は [検証結果](../catalog/evidence/office/verification.json) です。

[実M365 Copilotの生成ケース](../catalog/generated/office-three-apps/README.md)では、新しい本文・保存名を指定した16操作を手直しせずPADに貼付け・実行し、3成果物の内容を確認しました。生成原文はPADによる改行・末尾改行の正規化があるため、再コピーとの命令行一致です。アプリの自動Run経路の試験ではありません。

専用フロー名はユーザーが用意した `test`、基本例の採取先はMain・OfficeWord・OfficePowerPointです。ほかにOfficeOpenSamples（設定差分の採取用）、OfficeRoundtrip、OfficeCopilot、OfficeReopenを追加しました。OfficeOpenSamplesは独立した設定例の採取用であり、そのまま通し実行するものではありません。Power Fxの設定スイッチ自体はこのフローで個別に再確認していません。コピーした通常Robinでの貼付け・実行結果として扱います。

### Copilotへの渡し方

[pad-robin-prompts.md](../pad-robin-prompts.md)の全文をCopilotへ渡し、末尾に「作業目的・対象ファイル・対象範囲・出力先・期待する結果」を追記してください。Officeの原文22例はプロンプトに含めてあります。採取フォルダーのパスを実際の対象と取り違えないよう、依頼の対象を優先します。

例：「既存のExcelブックのA1:B2を読み取りたい。見出しはない。読み取り専用で開き、変更せず閉じる。必要な前提と貼付け用Robinを出して」。これは依頼の書き方であり、その任意ファイルで検証済みという意味ではありません。

未採取の書式・数式・表・図形・グラフ・テンプレート・マクロ等は追加の実例が必要です。今回、App.ps1の実行許可集合は拡張していません。カタログの `controller_support: not_implemented` のフローは、契約試験でアプリが拒否することも確認します。

## 1設定例を収録する手順

1. 現在のPAD版・言語・Power Fx設定を確認し、専用の採取フローを開く。業務文書を使わず、専用フォルダーに合成データを準備する。
2. 左欄を検索して実際のカテゴリ名・アクション名を記録し、フローへ追加する。検索結果の一部を全アクション一覧とは扱わない。
3. 設定項目と合成値、前提となるインスタンス・変数・UI要素を記録する。コピー前のクリップボードをメモリーに保持し、原私的データを記録しない。
4. 追加したアクションをコピーして原文を `catalog/actions/<action-id>/<variant>.robin` にUTF-8 BOMなしで保存する。原改行を保持し、SHA256を記録する。依存する操作を含む組合せも `catalog/flows/` に保存する。
5. 設定を一つだけ変更して再コピーする。命令名・引数・列挙値・出力型の差分を記録し、異なる設定の引数を混ぜない。
6. 空の専用サブフローへ再貼付けし、再コピー原文とのバイト一致を確認する。保存・実行・成果物の再読取りと表示確認を別々に記録する。コピーで確認できても実行失敗なら失敗として残す。
7. 既存の `catalog/index.json` と同じ形式で実測した例だけを登録する。設定値や依存条件を含む証拠を収録し、プロンプトにはその原文を反映する。未採取の行は索引に登録しない。
8. Copilotへプロンプト・関連例・合成データの新しい依頼を渡す。元の採取例とは異なる値・対象範囲で生成し、生成原文→PADへの貼付け→実行→成果物を照合する。手直しした場合は変更を明記し、無修正成功と区別する。

クリップボードは採取中に変化するため、最後に自分のコピーが残っている場合だけ元の内容へ戻します。入力文書と無関係な画面や認証情報を証拠に含めません。

## 完了の判定

各例について、左欄からの追加、設定、コピー、再貼付け一致、保存、実行、成果物確認、Copilot生成の成否を区別します。「未実施」を成功扱いしません。少なくともExcelとWordの開く→読み書き→別名保存、およびPowerPointで実際に利用できる経路を確認し、異なる依頼で通し検証できるまではOfficeの汎用対応完了とはしません。

このプロンプトの利用と、アプリの自動Runへの接続は別です。アプリで利用するには、インスタンスや変数の依存、対象ファイルの範囲、保存・終了の扱いを検証器と実行経路へ接続し、その経路でも検証する必要があります。
