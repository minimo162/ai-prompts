# 実アクションから汎用エージェントへ

目的は、PADの左パネルにあるアクションを実際にフローへ追加し、コピーしたRobinを根拠にCopilotが多様なフローを組み立てられるようにすることです。CSVは利用例の一つで、UIやエージェントの操作集合をCSVに限定しません。

## 採取の単位

1件は「左パネルのアクション名＋設定バリエーション」です。同名でも選択肢によってRobinが変わるため、基本設定だけを全設定の仕様とみなしません。

各採取記録に次を含めます。

|項目|記録する内容|
|---|---|
|環境|PADの製品版、言語、Power Fxの状態|
|UI|カテゴリ、アクション名、設定画面の項目名と実際に入力した合成値|
|Robin|フローへ追加した後にコピーした原文とSHA256。推測・整形したコードで置き換えない|
|変数|入力に必要な変数、出力変数、前提となるインスタンスやUI要素|
|差分|一つの設定だけを変えて再コピーしたときのRobin差分|
|確認|追加、コピー、再貼付け、保存、実行、結果検査を別々に記録|
|依存|Excel/PADブラウザー拡張、認証、接続、UI要素等の必要条件|

個人ファイル・認証情報を例にせず、専用の採取フローと合成データを使います。業務フローを採取先にしません。コピーによるクリップボード変更も記録します。

## 広げ方

まず左パネルで見えるカテゴリ・アクションを一覧化します。その上で変数、テキスト、リスト/データテーブル、条件/ループ、ファイル/フォルダー、Excel、ブラウザー、UI操作、その他の順に、実在するアクションを採取します。この列挙は調査順の提案であり、未観測のアクション名やRobin構文の仕様ではありません。

UI要素やインスタンスを参照するアクションは、その参照を作る前段も採取します。Robin文字列だけで再利用できない依存を「貼るだけで動く」と扱いません。外部送信・削除等を伴うアクションの採取は、設定/コピーの確認と実行試験を分けます。

## プロンプトへの反映

`pad-robin-prompts.md`の既存ルールを維持し、採取済み例を追加します。Copilotには必要なカテゴリの実例と依存条件を渡し、設定値の置換とアクションの組合せを行わせます。存在しないパラメーター名・選択肢を補完させません。実例が不足する場合は、不足しているアクションと設定を明示させて追加採取します。

次に、異なる業務を自然文だけ変えて生成し、再貼付け・実行・結果確認まで検証します。業務ごとにアプリ本体を追加実装しないこと、途中の条件変更や失敗から観測に基づいて再計画できることを汎用性の評価に含めます。

## アプリへの接続とUI

採取カタログは生成の知識であり、実行許可そのものではありません。現在のRobin検証器との対応を確認し、採取済みでも未対応の構文は実行前に説明します。単に任意Robinの実行を許可する変更にはしません。

UIは「目的」「作業対象」「計画/確認」「実行履歴」「結果と追加依頼」を中心に改めます。CSV固有の列設定等は必要になったときの補助入力へ移します。具体的なUI変更は、採取例を使った複数業務の通し確認と合わせて進めます。

最初の2アクション（リスト作成・項目追加）の設定/コピー/保存、元Mainの実行、空サブフローへの再貼付けと再コピー一致を確認しました。[カタログ](../catalog/README.md)に原文と索引を保存しています。他カテゴリ・設定バリエーション、Copilot生成、アプリ実行経路との接続は未完了です。既存プロンプトの過去の実機確認と、新しい採取結果を区別します。

続いて「変数の設定」の通常文字列・特殊文字入り文字列を採取し、日本語・パーセント・引用符・バックスラッシュを含む実行値を確認しました。現在3種類・4設定例です。全一覧取得はUIの仮想化への対応が残っているため、対象検索による個別採取も併用します。

「テキストを置換する」の通常/正規表現の2設定も追加し、4種類・6設定例になりました。どちらも保存・実行して結果を確認しています。設定で命令名と引数の集合が変わるため、バリエーションを分けてプロンプトに収録しています。

最初の[Copilot生成ケース](../catalog/generated/list-and-regex/README.md)では、採取例とは異なる変数名・入力値の4アクションを実M365が生成し、コード変更なしの貼付け/再コピー完全一致、保存・実行、期待値一致まで確認しました。アプリのRunループによる自動実行とは区別します。次はこの実例を基にアプリの操作・変数依存検証と生成経路を接続し、汎用UIへ進めます。

## アプリ接続の現在地

`Test-AgentRobin`と`Get-AgentPlannerRules`に、採取済みのリスト作成・文字列項目追加、通常/正規表現置換を追加しました。リスト追加先は確実にリスト型、置換入力は確実にテキスト型であることを確認します。IF/ELSEとELSEなしの分岐後も型を合流させ、不明な場合は拒否します。テキストリテラル内の`%%`はリテラルのパーセントとして解析しますが、元のRobinや本文を書き換えません。ファイルパスの動的参照は引き続き拒否します。

UIは汎用依頼欄を先頭に置き、CSV分類を折りたたみの補助へ移しました。デスクトップ/狭幅の順序、既存CSVの確認・停止・復旧・履歴は実Edgeで検証します。新しいRobin契約試験は`tests/Test-RobinCatalog.ps1`、全体入口は`tests/Run-NonLiveTests.ps1 -Suite All`です。

この追加形式の検証器への接続は確認しましたが、アプリの自動Runから新操作を含む実M365/PADを完走した証拠はまだありません。既存の所有済み専用フロー、結果観測、次の計画への引継ぎを含めて確認する必要があります。他カテゴリ採取・全一覧も引き続き未完了です。

その後、正規表現置換と新規保存の1ケースで[自動RunのDONEまで確認](general-agent-live-2026-09-07.md)しました。成功済み処理を繰り返す問題を観測し、コード生成と完了判断を分離、入力の読み取り証拠も判断へ追加しています。PADは1回、完了判断は1回でした。他カテゴリ・複数業務・追加依頼や復旧の検証は残っています。
