1. T03: 拡張子が .txt と等しいかを厳密に判定してElseへ分岐
確認済みの方法

フォルダーから取得した各ファイルは、For eachの反復変数 CurrentFile として扱われます。Ifの第1オペランドでは、変数ピッカーから CurrentFile > .Extension を選択し、演算子を「と等しい (=)」、第2オペランドを文字列 .txt に設定します。

PADから採取された条件の原文は、CurrentFile.Extension と .txt の等価比較です。その直後にElseを置く構成もPADから採取されています。パス全体に .txt が含まれるかを調べる Contains は部分一致であり、厳密な拡張子判定の根拠には使えません。

型と処理構成
Files: フォルダー内ファイルのリスト
CurrentFile: For eachで取り出すファイル変数
CurrentFile.Extension: 拡張子のプロパティ
.txt: 比較対象の文字列
true側: .txtファイルの処理
Else側: それ以外のファイルの処理

件数を数える構成では、TxtCount と OtherCount を数値の0で初期化し、加算アクションには文字列ではなく変数参照を渡しています。変数名を文字列リテラルとして渡した形はDesignerエラーになったため、成功例には含まれていません。

再貼付け・実行結果

Folder.GetFiles、For each、拡張子判定、If／Elseを含む原文は、別の空フローへ無修正で貼り付け、保存、再コピーされ、SHA一致が確認されています。

合成ファイル4件を使った2回の実行では、次の結果が確認されています。

.txt: 2件、If側
.csvと.md: 合計2件、Else側
TxtCount=2
OtherCount=2
最後に読み取った内容は alpha 日本語
入力4ファイルのSHAは不変

件数を持たず、Else内で何もしない最小構成も、別フローで2回実行されています。根拠原文は catalog/flows/t03-extension-branch/capture-pad-copy-20260912.robin、主な証拠は catalog/evidence/t03-ext-verify-acceptance-20260912.json と catalog/evidence/t03-ext-min-acceptance-20260912.json です。

未確認の境界

次は依然として未確認です。

.TXTなど、大文字小文字が異なる拡張子
x.txt.bakのような複合的な名前
親フォルダー名に .txt が含まれる場合
.Nameまたは .NameWithoutExtensionを使う判定
サブフォルダーを含める設定

したがって、確認済みといえるのは、今回の合成データ環境で CurrentFile.Extension を小文字の .txt と等価比較した範囲です。

2. T09: WAIT 500の実待機時間と貼り付け前の準備
実際の待機時間

PADの WAIT n における n の単位は秒です。したがって、WAIT 500は 500秒、つまり8分20秒待機します。ミリ秒ではありません。

2026年9月12日の通し実行では、Edge起動、入力、クリックまで数秒で進み、PAD上で「500 秒を待機します」と表示されました。その後、約8分20秒経過してから結果取得とブラウザー終了まで完了し、AttributeValue=T09-clicked が確認されています。2回の実行証拠が記録されています。

以前の80秒から207秒で停止した試行は、500秒の待機中に監視を打ち切ったものです。その記録だけをWebAutomation失敗の証拠とは扱えません。90秒以内の完了条件では、WAIT 500のままでは成立しません。実測例をそのまま確認する場合、監視上限は9分以上必要です。

フロー側で事前に必要な準備

通常チャットで生成される6行のRobinには、ControlRepository、つまりUI要素のセレクターや画像データが含まれません。そのため、貼り付け先フローには次の3要素が事前登録されている必要があります。

Input text 't09-input'
Button '実行'
Paragraph '未実行'

実測済みの準備方法は、ControlRepositoryを含む採取原文 catalog/flows/ui-t09-local-roundtrip/roundtrip.robin を貼り付け先フローへ一度貼り付け、3要素を取り込んだ後、その6アクションを削除してから生成Robinを貼り付ける手順です。

また、ローカルテストページ t09-local-test.html を指定されたローカルURLで表示でき、Edge用PAD拡張機能が接続できる環境が、成功した実測の前提です。UI要素は実画面のId属性から捕捉されており、推測したセレクターではありません。

確認済みの実行順

確認されている順序は、Edge起動、入力欄への置換入力、実行ボタンの左クリック、500秒待機、結果段落の Own Text 取得、Edge終了です。この順序を変更した構成は、今回の確認範囲には含まれません。

実測では次の型と値が使われています。

CatalogList: リスト
リスト内容: CatalogItem、SecondItem
インデックス: 数値の0
