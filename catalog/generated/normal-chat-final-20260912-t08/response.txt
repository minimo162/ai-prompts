以下は、指定した欠損ファイルの読取りエラーを既定ハンドラーで捕捉し、ErrorHandledDefault と LastError だけを確認する案です。書込み、完了マーカー、公開処理は含めません。

1. 前提・対象範囲・未確認点
目的: 存在しない合成ファイルをUTF-8で読み取り、ファイル未検出時のエラー状態だけを記録する。
入力: C:\Users\yuuki\ai-prompts\catalog\fixtures\text\t08-missing-20260910.txt
出力変数:
FileContents: 読取り成功時のテキスト。今回は生成されないことを確認する対象
ErrorHandledDefault: 既定ハンドラーが実行されたことを示す文字列true
LastError: 「最後のエラーを取得」で生成されるエラー情報
保存先・上書き: なし
成功条件:
フローが未処理エラーで停止しない
ErrorHandledDefault が true
LastError のプレビューに「ファイルが見つかりません」が含まれる
ファイル書込みや完了マーカーが一切実行されない

根拠環境はPAD 2.71.115.26224、日本語UI、Power Fx OFF、合成データです。既定の「すべてのエラー」ハンドラーは欠損ファイルで2回完了し、LastError に「ファイルが見つかりません」が表示された記録があります。一方、名前付きカスタムエラー FileNotFound はランタイムエラーが残ったため、この案では使用しません。

この組合せは、ブロック部分と「最後のエラーを取得」を別々にPADから採取して組み合わせ、合成欠損ファイルで2回実行した参照例です。単一のクリップボード原文として採取された完成フローではありません。

2. PADで先に確認する設定

対象サブフローは、書込みや公開処理を含まない新規の検証用サブフローにしてください。

指定パスにファイルが存在しないことをエクスプローラーで確認します。
ブロック エラー発生時 の処理対象をすべてのエラーにします。
エラー発生後は続行する設定にします。
エラーの再スローは無効にします。
最後のエラーを取得 は保存先を LastError、エラーの消去をオンにします。PADから採取された該当原文は ERROR => LastError Reset: True です。
このサブフローの後ろには、書込み、送信、公開、削除、完了マーカーを置かないでください。
3. 貼り付け用Robin

対象: 新規の検証用サブフロー全体。既存フローへ追加する場合は、後続処理から切り離された範囲へ貼り付けてください。

[code block: see robin.txt (indentation preserved there)]
BLOCK
ON BLOCK ERROR
SET ErrorHandledDefault TO $'''true'''
END
File.ReadTextFromFile.ReadText File: $'''C:\Users\yuuki\ai-prompts\catalog\fixtures\text\t08-missing-20260910.txt''' Encoding: File.TextFileEncoding.UTF8 Content=> FileContents
END
ERROR => LastError Reset: True

読取りアクションの命令名、UTF-8設定、出力変数、およびWindowsパスのバックスラッシュ表記は、PAD-Robin-Knowledge-Bundleに収録された欠損ファイル用の実測参照例に基づいています。

4. デザイナー上の確認

貼り付け直後に次を確認してください。

アクション順が、エラーブロック、欠損ファイル読取り、最後のエラー取得になっている
BLOCK と2つの END の対応にデザイナーエラーがない
ハンドラーが名前付き FileNotFound ではなく、既定のすべてのエラーになっている
ErrorHandledDefault は文字列として設定されている
LastError は「最後のエラーを取得」の出力になっている
FileContents を参照する後続アクションがない
書込み、完了マーカー、公開、送信、削除の各アクションが存在しない

貼り付け後にハンドラー設定が異なる場合は、その場で推測修正せず、該当アクションの設定画面とPADから再コピーしたRobinを採取してください。名前付きカスタムエラー一致は成功範囲に含まれていません。

5. 実行と期待結果
フローを保存します。
指定ファイルが存在しない状態で1回実行します。
実行後の変数ペインで次を確認します。
ErrorHandledDefault = true
LastError に「ファイルが見つかりません」
FileContents が正常な読取り結果として生成されていない
出力ファイルや完了マーカーが新規作成されていないことを確認します。
エラーが消去された状態で再実行し、同じ結果になることを確認します。
結果が異なる場合は、エラー全文、該当アクション、ハンドラー設定、PAD版、実行後の3変数の状態を保存してください。生成コードを書き換えて成功扱いにはしません。

確認範囲: 欠損ファイル、UTF-8読取り、既定の全エラーハンドラー、エラー後の変数設定、最後のエラー取得までです。エラー内容のファイル書込み、ログへの追記、条件分岐による後続処理の抑止は、このナレッジでは組合せ実測されていないため追加していません。
